# Phase 2 시나리오 검토표

평가용 30개와 개발용 10개의 질문·기대 행동을 모은 목록입니다. 아래 링크의 JSON이 원본이며, 수치 정답은 생성본의 `answer_key.json`을 참조합니다. 영어 설계와 자세한 실행 방법은 [Phase 2 문서](../../Phase/Phase2_EvaluationScenarios.md)에 있습니다.

- `expect`: 마지막 답변의 기대 결과와 전체 실행에서 기대·금지되는 행동.
- `checkpoints`: 1부터 시작하는 앞선 사용자 턴의 답변과 그 시점까지의 행동. S09와 S26에 사용합니다.
- `reviewCriteria`: 숫자·키워드 검사에 더해 Phase 5에서 사람이 확인할 의미 기준.
- `expectedStatus`: 도구 결과의 데이터 상태. 미입력·계획 정지·휴무일·기간 밖을 구분합니다.
- 모든 시나리오에서 실제 이슈 테이블은 그대로여야 합니다. `operator`도 텍스트 환경에서는 초안까지만 생성합니다.
- 모델에는 `turns`만 전달합니다. 이 목록의 기대 행동, 정답 참조와 정답표를 모델에 보내지 않습니다.

## 작성 검수와 실행 구분

2026-10-23에 질문의 라인·기간·대화 문맥과 실제 사건 날짜를 확인했습니다. 문맥이 부족한 질문은 되묻기를 정답으로 지정했습니다. 주간 비교 기준은 고정 시각 `2026-10-01 08:00`의 지난주 `9/21~25`, 2주 전 `9/14~18`입니다. 라인 생략 시 전체 6라인을 요약하며, 총생산·양품·달성률을 구분합니다.

Phase 2에서는 형식·참조·동결 검사를 완료했습니다. AI가 실제로 이 질문에 답하는 실행과 최종 채점은 Phase 5에서 진행합니다. 현재 작업 폴더에서는 다음 명령으로 동결을 검사합니다.

```sh
npm run scenarios:check
```

새 데이터 생성본은 새 식별값을 가지므로 별도 재동결 사유가 필요합니다. 자세한 절차는 [Phase 2의 생성본 설명](../../Phase/Phase2_EvaluationScenarios.md)을 따릅니다. 동결 후 질문을 바꾸면 `scenarios:check`가 실패하며, 다시 동결한 결과는 이전 평가 조건과 구분합니다.
